# 回答质量诊断

⚠ 与前一个 `bid-analysis` 的分工：那边是**从零开始做分析**，这边是**已有的回答坏了**。
`diagnose-capability` 管的是「整个能力不工作」（工具不出现、health 报红），
这里是**能力正常但这一次答得不好**。

---

## 零、⚠⚠ 先说清楚：哪些信号根本不存在

诊断的第一步是别去找不存在的东西。用户（和直觉）以为能查的四样，实际情况是：

| 以为能查 | 实际 |
| --- | --- |
| **工具结果质量标签 ✅/⚠️** | ❌ **不存在**。`✅`/`⚠️` 在 `src/` 下**零命中**。真实判据是 `assess_outcome()` 产出的【结果质量】**中文段落**，而且它**只被塞进模型上下文**（`agent.py:451-457`），**不进 SSE、不进日志** ⇒ 要看到它只能**重放**（第三步） |
| 相关性分数 | ✅ 能，`sources` 里全在 —— 但⚠ **闸门已经筛过一遍**，「分数低」几乎永远不是真原因（第二步） |
| 调没调对工具 | ✅ 能，但有折扣：`tool_call.query` 是 `peek_display()` 的**展示串**，不是模型传的原始参数（第一步） |
| 联网是不是搜到了垃圾 | ✅ 能，但要去**后端日志**看，SSE 里没有（第四步） |

### 三处证据源

| 来源 | 有什么 | 怎么拿 |
| --- | --- | --- |
| **SSE 事件流** | 路由、分数、工具成败、耗时 | 重打一发（见下） |
| **后端日志** | 联网那四段真相、撞顶丢弃、强制轮被拒 | `grep /root/autodl-tmp/backend.log` |
| **重放** | 【结果质量】、工具回传正文、结构化数字 | `replay.py`（第三步） |

## 一、先复现，拿证据

```bash
# ⚠ 中文请求体写成 UTF-8 文件（Git Bash 的 -d 会按 GBK 发出去 → 400）
cat > /tmp/q.json <<'EOF'
{"question":"<用户那句原话>","rerank":false}
EOF
curl -N -X POST localhost:8000/api/agent -H "Content-Type: application/json" \
     --data-binary @/tmp/q.json | tee /tmp/sse.txt
```

⚠ **务必沿用当时的开关状态**（`rerank` / `web_search` / `llm_provider`）——
诊断的是**那一次**的回答，开关不同就不是同一个实验。用户说「我开着联网」，请求体里就要有。

事件序列与字段含义见 `CLAUDE.md` 的「SSE 契约」。诊断只关心这四个：

| 事件 | 关键字段 |
| --- | --- |
| `tool_call` | `round` / `name` / `query`（⚠ 展示串） |
| `tool_result` | `ok` / `error` / `new_indices` / `known_indices` / `elapsed_ms` / `graph` / `pg` |
| `sources` | `sources[].score` / `.vector_score` / `.bm25_score` / `.rerank_score` / `.matched_by` / `.origin` |
| `done` | `total_ms` |

## 二、第 1 步：路由对不对

**判据**：`tool_call` 事件里出现了哪些 `name`，和问题的类型对不对得上。

| 问题类型 | 该调的 | 不该调的 |
| --- | --- | --- |
| 法规条文、政策口径 | `search_bidding_knowledge` | 图谱 / 采购库 |
| 「某企业/某标的物的交易记录、名单」 | `search_knowledge_graph` | ⚠ 采购库（重叠区） |
| 「按省份/金额/类别筛、精确条数、分组统计」 | `search_procurement_records` | ⚠ 图谱（重叠区） |
| 知识库没有的、有时效性的 | `search_web`（**要先拨开开关**） | — |

**注意三件事**：

- ⚠ **没调工具不一定是错**。预检索（和开关打开时的预联网）在模型第一轮**之前**就跑了，
  所以「模型直接作答」也可能是对的 —— 尤其检索类问题。
- ⚠ **`query` 是展示串不是原始参数**。四种形状：检索是查询词本身；
  图谱是「类型标签：实体」；采购库是「类别=学校，金额≥500000 元」；联网是「词（最多 N 条）」。
  **想看模型真正传了什么，只能重放（第三步）或跑 `eval/agent_eval.py` 的 `RecordingLLM`。**
- ⚠⚠ **图谱 vs 采购库是已知的重叠区，来回摇摆是正常行为**，不是故障。
  实测同一道题连跑 5 次是 3:2 分布。**别为单次摇摆改提示词** —— 那会动摇
  「实体/名单归图谱」，而列举型问题的强制首轮兜底正是靠它成立的。

**要确认「本轮到底挂了哪些工具」**（没挂出去的工具不可能被调）：

```bash
curl -s localhost:8000/api/health | python3 -c "
import json,sys; d=json.load(sys.stdin)
print('图谱:', d['graph_available'], '| 采购库:', d['pg_available'], '| 联网Key:', d['web_configured'])"
```

⚠ `available: false` 可能是「**还没试过**」而不是「连不上」—— 见 `diagnose-capability`。

## 三、第 2 步：检索质量（⚠ 这一节最容易被读反）

先说那条最容易搞反的：

> ⚠⚠ **`sources` 里的 `vector_score` 不可能低于阈值 0.72。**
> `_passes_gate()`（`retriever.py:98`、定义在 `:227`）在**编号之前**跑，
> 低于 `MIN_VECTOR_SCORE` / `MIN_BM25_SCORE` 的候选**根本没进 `sources`**。

⇒ **「分数低」不是一个可用的诊断结论** —— 能看到的都是过了线的。
真正能读出来的只有这四种形状：

| 形状 | 含义 | 下一步 |
| --- | --- | --- |
| `sources` **为空** | 闸门整批筛空 —— 要么真没答案，要么这次问法的字面跟语料差太远 | 换问法；或确认语料里有没有这东西 |
| `vector_score` **贴着 0.72~0.78** | 边际命中，勉强过线 | ⚠ 阈值是针对当前语料标定的，可能对这类问法偏松/偏紧 |
| `vector_score` **高（0.82+）但答案答非所问** | ⚠⚠ **向量分的盲区** —— 实测完全不相干的资料得 **0.8166** | **开重排**（见第五步），这是唯一治它的 |
| **`rerank_score` 有值** | 判「能不能回答」的那个信号：能答 ≈0.73 / 答不了 ≈0.50 | 若 top 的 rerank_score ≈ 0.50 ⇒ **语料里就是没有**，别再调参数 |

**看 `matched_by` 拆通道**（`["vector"]` / `["bm25"]` / 两者都有）：

- 只有 `bm25` ⇒ 靠**关键词**命中的。若是概念性问题，说明向量那路没帮上忙。
- 只有 `vector` ⇒ 语义相似但字面不重合。⚠ **这正是「答非所问」的高发形状**。
- 两者都有 ⇒ 命中较扎实。

⚠ **`rerank_score` 只在重排开启时才有值**。关了重排，那一格是 `null` ——
不是「重排给了 0 分」，是**这个判断压根没做**。

### ⚠⚠ 语料覆盖先于一切

「答不出」有个纯数据的原因，调什么参数都没用：**语料只有 74 条**。实测两个词的覆盖差 8 倍 ——
「单一来源」占 8 条，「竞争性谈判」只有 **1** 条。模型如实答了一半、明说另一半查不到，
**那是对的行为，不是失败**。诊断前先确认你要的答案在不在语料里：

```bash
curl -s -X POST localhost:8000/api/search -H "Content-Type: application/json" \
     -d '{"query":"<关键词>","mode":"hybrid","top_k":5}' | python3 -m json.tool | head -40
```

## 四、第 3 步：工具结果质量（**要重放才看得到**）

⚠ 这一格**没有 ✅/⚠️ 标签**，也**不在 SSE 里、不在日志里**。`assess_outcome()` 的产出
只被追加在 `role:"tool"` 消息的末尾，**只有模型读得到**。用户看到的「工具调用」折叠区里
没有它，所以用户说「它明明调了工具啊」和模型实际拿到的可能是两回事。

**重放**：

```bash
# 用 tool_call 事件里的 name + 你推测的参数，重跑一次
uv run python .claude/skills/debug-answer/replay.py 图谱 '{"query_type":"subject_suppliers","entity":"空调"}'
uv run python .claude/skills/debug-answer/replay.py 采购库 '{"contains":"空调","category":"幼儿园"}'

# 还原「当时本轮还挂着哪些工具」（会影响【结果质量】的第二行）
uv run python .claude/skills/debug-answer/replay.py 图谱 '{...}' --available 检索,图谱,采购库
```

输出三段，**前两段就是模型当时读到的原文**：① `_render_result()` 正文
② 【结果质量】段落 ③ 结构化结果（核对数字）。

⚠⚠ **重放不了检索那一格**：`search_bidding_knowledge` 要真 retriever，会抢 Qdrant 排他锁。
硬重放会得到 `'NoneType' object has no attribute 'search'` —— 那是**重放的用法问题，不是故障**。

### 【结果质量】什么时候会追加

`assess_outcome()` 只在工具**空手而归**或**失败**时追加。⚠ 但有个反直觉的分叉，**本次实测出来的**：

| 情况 | `error` 码 | 追加【结果质量】？ |
| --- | --- | --- |
| 工具查了、0 行（`ok=True`） | 无 | ✅ 会（「没有拿到任何结果」） |
| 工具返回 `ok=False` + 中文原因 | 中文原文 | ✅ 会（「本次调用失败」） |
| `unknown_tool` / `bad_query_type` / `bad_arguments` / `empty_query` / `duplicate_query` | 正确的码 | ❌ **不会** |

⚠⚠ **【结果质量】里的「本次调用失败」不等于「工具坏了」** —— `ok` 说的是
「**查询执行了没有**」，不是「查到了没有」。0 行照样 `ok=True`。

### ⚠ 一处已发现的错配（知道了免得误判）

`_SELF_CORRECTING_ERRORS`（`base.py:407-409`）的设计意图是「**参数写错时不插话**」，
但那道闸只认**引擎层**的错误码。两个 store 层的错误把 `error` 设成了**一长串中文原文**
而不是错误码，**漏出了闸** —— 实测：

| 情况 | 实际 `error` | 按设计 | 实际行为 |
| --- | --- | --- | --- |
| `group_by="星座"` | 中文原文 | 不该追加 | ⚠ **会追加** |
| 图谱 `entity` 留空 | 中文原文 | 不该追加 | ⚠ **会追加** |

后果：模型读完「group_by 只能是 city / county / … 之一」之后，
**又被追加一段**「本轮还挂着这些工具…请改调 search_bidding_knowledge…」。
是噪声，会挤占「把参数改对」这条更重要的指令 —— 但**不至于答错**（修正线索仍在第一行）。
⚠ 这是**已知的既有行为**，别在诊断时把它当成「模型乱换工具」的证据。

## 五、第 4 步：联网搜索是不是返回了垃圾

SSE 里**看不出来**（网页结果和知识库条目长得一样，都是 `sources` 里 `origin:"web"` 的条目）。
唯一的线索是**后端日志那一行**：

```bash
grep "联网搜索 ok=" /root/autodl-tmp/backend.log | tail -20
# 联网搜索 ok=True 原始=5 条 top=0.8468 闸门=0.70 → Source=5 新增=5 已知=0 丢弃=0 1832ms
```

**四段判读**（`agent.web_lookup()`，两条链路共用同一个函数，所以 `/api/chat` 和 `/api/agent` 都看得到）：

| 日志形状 | 真原因 | 处置 |
| --- | --- | --- |
| `ok=False` | 传输层失败（冷却 / 429 / 401 / 超时） | 查 Key、看冷却、稍后重试 |
| `原始=0 条` | Tavily 真没搜到 | 换关键词 |
| `原始=N 条 top=0.xx **低于闸门**` | **整批被闸门丢弃** | ⚠ 见下 |
| `新增=0 已知=N` | 全被判成「已见过」 | 正常（重复搜索） |
| `丢弃=N` | 撞上 `AGENT_MAX_SOURCES`（20）上限 | 见下 |

**`top` 低于 0.70 被整批丢** —— 这一条要分清是**对的**还是**误杀**：

- ✅ **对的**：网上真没这个东西，丢掉是实话（该保留「没搜到」的诚实回答）。
- ⚠ **误杀的**：Tavily **偶发**返回一批退化结果。实测同一句查询 11:41 拿到 `top=0.8263`、
  11:44 **同一句**拿到 `top=0.5356` → 整批丢弃 → 那次请求一条网页来源都没有。随后连打 12 次
  一次都没重现。**表现与「功能没生效」一模一样**（面板里只有知识库条目、正文不提联网）。
  ⇒ 先看日志的 `top=`，**别据此加「闸门失败就重试」**（真正没答案的查询本来就该整批丢）。

⚠ **`新增=0` 也可能是撞顶**：`registry.add()` 撞上限时会打一行 WARNING，
`丢弃=N` 那格就是它。撞顶后 `fresh`/`known` 双双为空，**形状与「真的一条没命中」完全一样** ——
日志是唯一分得开的地方。

## 六、第 5 步：给建议

⚠ **按「最可能有效」排序，且先说清楚哪些改不了。**

### 排序清单

| # | 措施 | 治什么 | 怎么给用户 |
| --- | --- | --- | --- |
| 1 | **开重排** | ⚠⚠ **「答非所问」的首选** —— CrossEncoder 判的是「能不能回答」，向量分判的是「像不像」 | 前端那个开关；关了的话 `sources` 里 `rerank_score` 是 `null` |
| 2 | **换问法/加术语** | 闸门筛空、`matched_by` 只有 bm25 | 用知识库里的**原词**问（比如「单一来源采购」而不是「独家采购」） |
| 3 | **开联网** | 时效性问题、语料里根本没有 | ⚠ 每次提问花 1 个 Tavily credit，答得出也照花 |
| 4 | **换检索模式** | `matched_by` 单一通道 | `mode` 可切 `hybrid`/`vector`/`bm25`；概念题偏 vector，术语题偏 bm25 |
| 5 | **换文本大模型** | 路由错、答非所问但资料是对的 | 前端那个循环胶囊（`llm_provider`） |

⚠ **第 1 条用户通常想不到**，但它是唯一能治「向量分高却答非所问」的手段 —— 实测资料完全
不相干也拿 0.8166，在阈值之上。**别漏了它。**

### ⚠⚠ 有三类问题，换什么都是白换

说清楚这个，比给一堆措施更有用：

1. **语料里没有的东西**（「竞争性谈判」只有 1 条）—— 开重排、换模型都变不出语料里没有的内容。
   判据：**开着重排时 top 的 `rerank_score` ≈ 0.50**（模型对谁都「无感」）。
2. **时间趋势类问题** —— 这份数据是 **12 天的快照**（2023-10-09~10-20），不是时间序列。
   见 `bid-analysis` 的「陷阱 3」。
3. **语料里的坏数据** —— 74 条里有一条 `qa-0046` 参考答案残缺（20 字、冒号结尾、后面没内容），
   它的 `context_recall=0.0` 是**指标正确报出了坏数据**。要修得改 xlsx 并重新 ingest。

## 七、症状 → 真原因 速查

| 症状 | 先查 | 真原因多半是 |
| --- | --- | --- |
| 答非所问，资料看着还挺像 | `sources[].vector_score` | ⚠ **向量分的盲区** —— 开重排（不是「检索坏了」） |
| 说「暂未找到依据」 | `sources` 是否为空 | 闸门整批筛空 = 语料里没有，或问法字面差太远 |
| 调了工具却还是没答上 | 重放看【结果质量】 | 工具真返回了 0 行（前端看不到这段，**只能重放**） |
| 「它没查就瞎答」 | `tool_call` 事件 | 可能**没调工具是对的**（预检索已够）；先看 `sources` 非不非空 |
| 模型把工具名/参数写进正文 | 后端日志 `grep 漏进正文` | 泄漏恢复机制（⚠ **不是** `markup_leak` —— 那是 `/api/chat` 独有的信号，Agent 侧不发） |
| 答案在 max_tokens 处断了 | 日志 `在 max_tokens 处截断` | 调大该供应商的 `max_tokens` |
| 同一句话两次答得不一样 | — | **不是故障**。工具路由跨次会翻（实测 3 次里 `[采购库]`/`[未调]`/`[未调]`） |
| 图谱/采购库数字对不上 | 两边 `resolved` / `filters` | ⚠ **口径不同，不是错** —— 见 `bid-analysis` 陷阱 1 |

⚠ **单次结果不作数**：判分噪声底是**均值 ±0.005、单题 ±0.28**。要下结论就跑 3 次看倾向。

## 八、重放工具自检

```bash
uv run python .claude/skills/debug-answer/replay.py 采购库 '{"contains":"量子计算机"}'
```

**判据**：应当看到 ① 正文里「没有查到符合条件的记录」、② 【结果质量】里
「本次调用没有拿到任何结果（库里匹配到 0 行）」、③ `total=0` 但 `ok=True`。

若 ② 是空的，说明 `assess_outcome()` 的判据变了 —— 去看 `tools/base.py:412-465`。

⚠ 重放的是**当前**数据。库被 `to_postgresql.py` 重灌过的话数字会与当时不同 ——
那时以**形状**为准（有没有结果、闸门丢没丢），别硬比具体数字。
