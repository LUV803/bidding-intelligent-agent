# 项目文件结构说明

> 这份文档回答两个问题：**每个文件是干嘛的**，以及**改了它之后该跑什么**。
> 判据都是对着代码核过的，不是猜的。最后更新：2026-10-08。

## 0. 一句话地图

```
                    ┌── 入库（跑一次）──┐
   Excel ──► dataset ──► embedding ──► Qdrant
                  └──► jieba ──► BM25 索引

                    ┌── 每次请求 ──────────────────────┐
   问题 ──► retriever ──► [向量 + BM25] ──► RRF ──► 闸门 ──►（可选）重排 ──► 来源
                    └──────────────────────────────────┘
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
      /api/chat 写死流水线            /api/agent 模型自主调工具
      （前端打不到，但没删）          （前端唯一入口）
                                              │
                        ┌─────────────────────┼─────────────────────┐
                        ▼                     ▼                     ▼
                  search_bidding_         图谱 / 采购库 /      联网 Tavily / Exa
                  knowledge（检索）        load_skill（技能）   （每请求挂的）
                                              │
                                       可搬进独立进程当 MCP 服务器
```

两个进程：后端 `src/bidding_qa/`（FastAPI :8000）+ 前端 `frontend/`（Next.js :3000）。
`batch/` 是**独立的数据准备链路**，不在问答链路里，跟线上一点关系都没有。

## 1. 后端 `src/bidding_qa/`（33 个文件，约 12800 行）

### 1.1 入口与配置

| 文件 | 干什么 |
| --- | --- |
| `__init__.py` | 包定义 + `__version__`，6 行 |
| `__main__.py` | `python -m bidding_qa` 的入口：`uvicorn.run(api.app, ...)`。**只有这里读 `api_host` / `api_port`** |
| `config.py` | 全部配置的单一出口。`Settings`（pydantic-settings，`extra="ignore"`）+ 模块级 `settings = get_settings()`。**import 期就设 HuggingFace 镜像环境变量**，所以任何用 `sentence_transformers` 的模块必须先 `from .config import settings`。末尾挂着启动配置体检（`_report_startup_config`），缺 Key 时逐个点名 |
| `schemas.py` | 所有 API 的请求/响应 pydantic 模型：`ChatRequest`、`Source`、`GraphResult`、`PgResult`、`VisionResult`、`ConversationUpsert`、`FeedbackRow`…**前后端的契约都写在这里** |

**改 `config.py` 的字段 / 体检表之后跑**：`uv run python scripts/probe_config.py`（33 条，全离线）
⚠ 加配置项要三处一起改：`config.py` / `.env` / `.env.example`。漏一处会被 `.env` **静默覆盖**（这坑栽过四次）。

### 1.2 入库链路（一次性）

| 文件 | 干什么 |
| --- | --- |
| `dataset.py` | 读 `data/processed/问题答案样例数据.xlsx`（`问`/`答` 两列）→ 去重 → 返回 `list[dict]`。81 行数据行，去重后 **74 条** |
| `embedding.py` | `BAAI/bge-small-zh-v1.5`（512 维）。文档侧直接编码；**查询侧按 BGE 官方要求加中文检索指令前缀** |
| `vector_store.py` | Qdrant 封装。`cloud` / `local`（嵌入式文件，无需 Docker）/ `auto`（连不上云就静默回退本地）三种模式 |
| `bm25_index.py` | jieba 分词 + `BM25Okapi`。索引持久化到 `data/index/bm25_index.json`，启动时直接加载 |
| `ingest.py` | 串起上面四个：Excel → 向量 + BM25。`--recreate` 全量重建 |

⚠ **两处索引必须同时重建**，否则向量库与 BM25 的 `doc_id` 会对不上。
⚠ 本地 Qdrant 是**排他锁**：起了 API 就不能再跑 ingest，跑评估前通常也得先停后端。
**跑**：`uv run python -m bidding_qa.ingest --recreate`

### 1.3 检索链路（每次请求）

| 文件 | 干什么 |
| --- | --- |
| `retriever.py` | **唯一入口** `search()`。串起向量 → BM25 → RRF → `_passes_gate()` →（可选）`_apply_rerank()` → `_gate_by_rerank()` → `_to_source()`。251 行，是检索层的大脑 |
| `hybrid.py` | RRF 融合 + 片段抽取（滑窗取 jieba 词重合度最高的句子）+ 关键词高亮。163 行 |
| `reranker.py` | CrossEncoder（`BAAI/bge-reranker-base`，1.1GB）二次精排。**懒加载 + 吞掉所有异常回退到融合顺序**；`warmup()` 即使 `RERANK_ENABLED=false` 也预加载 |

**三条标定阈值**（都是对**当前这份语料**实测的，换库必须重测）：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `MIN_VECTOR_SCORE` | 0.72 | 向量分准入线 |
| `MIN_BM25_SCORE` | 8.0 | BM25 分准入线（任一达标即保留） |
| `MIN_RERANK_SCORE` | 0.55 | 重排分准入线（比上面两个准，因为它判的是「能不能回答」而非「像不像」） |

⚠ **关键不变量**：引用序号 `[n]` 在**闸门过滤之后**才分配，保证正文里的编号连续。改动排序/过滤逻辑时别破坏它。

**改检索之后跑**：`uv run python scripts/eval_rag.py --no-llm`（零 API 成本、秒级，先看召回坏没坏）

**改 `clients/llm_factory.py` / `ChatRequest` / `HealthResponse` 之后跑**：`probe_llm_provider.py`（64 条，全离线）

### 1.5 工具层 `tools/`

| 文件 | 干什么 |
| --- | --- |
| `tools/base.py` | 工具引擎。`BaseTool` / 注册表 / `execute_tool` / `recover_tool_calls` / `SourceRegistry` / schema 生成（`to_openai_schema` + 清洗层）/ `assess_outcome`（结果质量检查）/ **MCP codec**（`outcome_to_payload` / `outcome_from_payload`）。864 行 |
| `tools/rag_tools.py` | **六个工具的具体定义** + `TOOL_*` 常量 + `TOOL_SCHEMAS` / `TOOL_NAMES` / `tools_for(enable_web)` / `web_lookup`。1059 行，全仓最大的源文件 |
| `tools/__init__.py` | 把 `base` 和 `rag_tools` 都拉进来。⚠ 只 import `base` 的话默认池是空的，`recover_tool_calls()` 会把一切泄漏标记静默丢掉 |

**六个工具**：

| 工具名 | 回答什么 | 挂出去的条件 |
| --- | --- | --- |
| `search_bidding_knowledge` | 法规条文、政策口径、办事流程 | 无条件 |
| `search_knowledge_graph` | 实体之间的关系（某企业的供应商、某标的物谁供过） | `graph_store.ENABLED` |
| `search_procurement_records` | 项目级明细与统计（按省份/时间/金额筛、分组统计） | `pg_store.ENABLED` |
| `load_skill` | 把一份技能说明书读进上下文 | 无条件 |
| `search_web` | 知识库里没有的、有时效性的东西（Tavily） | 用户开关 ∧ 配了 Key |
| `search_web_exa` | 换个引擎再搜一次（Exa，Tavily 结果不理想时） | 上一条 ∧ 配了 Exa Key |

**改工具层之后跑**：`probe_recover.py`（离线）+ `probe_quality.py`（离线）+ `probe_tools.py`（真机）

### 1.6 Agent 循环

| 文件 | 干什么 |
| --- | --- |
| `agent.py` | `run_agent_stream()`：预检索 →（可选）预联网 → 模型多轮工具循环 → 强制收尾轮。634 行。还负责**泄漏标记恢复**、`answer_reset`、`SourceRegistry` 全局编号、列举型问句首轮强制图谱 |

**事件序列**：`start → sources → [(reasoning|delta|tool_call|tool_result|sources|answer_reset)*] → done`

**三条不能破的不变量**：
1. 工具执行**永不抛异常**（漏掉 `role:"tool"` 消息会让下一轮请求直接 400）
2. 循环**必定收口**（轮数用尽还要跑一轮 `tool_choice="none"` 强制收尾）
3. 引用编号**全局唯一**（`SourceRegistry`，上限 `AGENT_MAX_SOURCES=20`）

⚠ `agent_max_rounds`（5）与 `agent_max_sources`（20）**是耦合的**，改一个要看另一个。

### 1.7 可选能力模块

| 文件 | 干什么 | 开关 |
| --- | --- | --- |
| `graph_store.py` | Neo4j 知识图谱。**9 个查询类型**走 `_HANDLERS` 白名单分派，**绝不接受模型给的 Cypher**；只读会话；`query()` 永不抛。793 行 | `NEO4J_URI` 非空 |
| `pg_store.py` | PostgreSQL `bid_records` 表（8751 行）。结构化过滤器 + **列名白名单拼 SQL**，值全走 `%s`；连接参数里设 `default_transaction_read_only=on`。805 行 | `POSTGRES_HOST` 非空 |
| `conv_store.py` | 对话历史持久化。`conversations` + `messages` 两张表，整个前端 `Message` 对象进 `payload jsonb`。781 行 | 同上（**共用开关**） |
| `skill_store.py` | 技能说明书：把「固定流程」做成可按需加载的长文本。`catalogue()` 的描述常驻，正文按需 `load_skill`。渐进式披露 | 无条件 |
| `skills/` | 两份运行时技能说明书：`bid-analysis/SKILL.md`（端到端数据分析）、`debug-answer/SKILL.md`（回答质量诊断） | — |
| `web_search.py` | Tavily 联网搜索。**异步 httpx 直接 await**（不套 `to_thread`）；30 秒失败冷却；空结果重试 2 次；准入线 `WEB_SEARCH_MIN_SCORE=0.70`。409 行 | `TAVILY_API_KEY` 非空 ∧ 用户开关 |
| `mcp/web_search_exa.py` | 第二个引擎 Exa，经 MCP 协议调托管端点。373 行 | 上面两条 ∧ `EXA_API_KEY` 非空 |

⚠ **图片解析与上面这些形状不同**：它**不是 Agent 工具** —— 解析发生在上传那一刻（`POST /api/vision`），早于提问，模型决定不了。
⚠ `/api/health` 只能报**服务端默认**那家 LLM 与「配没配 Key」，它没有请求上下文。

### 1.8 MCP（两套，别混）

| 文件 | 干什么 |
| --- | --- |
| `mcp/mcp_client.py` | **我们当客户端**连 Exa 的托管端点。刻意做小：连 → 握手 → 调一次 → 断开。164 行 |
| `mcp/mcp_bridge.py` | **我们当客户端**连**自己的** MCP 服务器（下面那个）。与上面刻意**不合并**：它读 `structuredContent`、有 `list_tools()`、**失败一律抛 `BridgeError`**。347 行 |
| `mcp_server.py` | **我们当服务端**：把图谱 / 采购库 / 技能三个工具搬进独立进程。`python -m bidding_qa.mcp_server`。469 行 |
| `mcp/__init__.py` | 三个子模块的汇总导出。⚠ 包名叫 `bidding_qa.mcp` 而不是 `src/mcp`，否则会**遮蔽官方 `mcp` SDK 包** |

| | 开关 | 默认状态 |
| --- | --- | --- |
| Exa（`mcp_client` + `web_search_exa`） | `EXA_API_KEY` 非空 ∧ 用户开联网 | 跟着联网开关走 |
| 自建服务器（`mcp_server` + `mcp_bridge`） | `MCP_SERVER_URL` 非空 | **留空 = 工具跑在进程内，是默认且健康的状态** |

**改 `mcp_server.py` / `mcp_bridge.py` / codec 之后跑**：`probe_mcp_server.py --offline`（70 条，全离线）

### 1.9 接口层

| 文件 | 干什么 |
| --- | --- |
| `api.py` | FastAPI 应用。**两条问答链路**：`/api/chat`（写死流水线，前端打不到但**没删**）与 `/api/agent`（前端唯一入口）。外加 `/api/search`、`/api/vision`、`/api/health`、6 个对话历史路由、3 个反馈路由。781 行 |

**🎯 最容易被误解的一点**：`/api/chat` 还在。它和 `/api/agent` **并存**，探针还钉着它的 SSE 契约，只是 `frontend/` 里再也打不到它。**改 Agent 代码时不要顺手删它。**

**限流**：slowapi，桶是**每个端点**的（`/api/chat` 120/分钟、`/api/agent` 另有 120/分钟，不是加起来 120）。`/api/health` 整个豁免。`RATE_LIMIT_PER_MINUTE=0` 关闭。

### 1.10 独立脚本（不在包内）

| 文件 | 干什么 |
| --- | --- |
| `src/database/to_postgresql.py` | 弹窗选 xlsx → 整表灌进本机 PostgreSQL 的 `chatbot` 库。**默认整表替换**（单事务 `TRUNCATE` + `COPY`），`--keep` 才是追加。552 行。⚠ 它自己解析 `.env`，不 import `bidding_qa.config` |
| `src/rag_agent/__init__.py` | **uv init 的残留**，内容只是一句 `print("Hello from rag-agent!")`。这个包没有任何用途 —— 可以删 |

### 3.3 真机探针（需 Neo4j/PG + API Key）

`probe_tools.py` / `probe_graph_tool.py` / `probe_pg_tool.py` / `probe_recover_e2e.py` —— 验模型会不会在**对的时机选对的工具**。

## 5. 数据准备 `batch/`（一次性，与线上无关）

这条链路把一份招标 Excel 变成 Neo4j 图谱 + PostgreSQL 表。**顺序不能乱**：

| # | 脚本 | 输入 → 输出 |
| --- | --- | --- |
| 1 | `build_batch_jsonl.py` | 招标 Excel → `batch_input.jsonl`（每条项目名称一个 chat 请求） |
| 2 | `run_batch.py` | 提交智谱 Batch → 轮询 → 下载 → `batch_output.jsonl` + `batch_budget.json` |
| 3 | `按custom_id排序.py` | `batch_output.jsonl` → `batch_output_sorted.jsonl`（服务端返回顺序不保证与输入一致） |
| 4 | `去重.py` | `抽取结果.xlsx` → `..._训练数据_2.xlsx`（同「项目编号+中标金额」保留 null 最少的那行） |
| 5 | `提数据_插标的物.py` | `batch_output_sorted.jsonl` + `_2.xlsx` → `_2_标的物.xlsx` |
| 6 | `统计数据_插交易频次.py` | `_2_标的物.xlsx` → `标的物_交易频次.xlsx` |
| 7 | `知识图谱_导出CSV.py` | `_2_标的物.xlsx` + 交易频次 → `_2_知识图谱.xlsx`（6 列） |
| 8 | `知识图谱_导入Neo4j.py` | 两个 CSV → **Neo4j**（中文标签版，8751 笔交易） |
| — | `to_neo4j.py` | ⚠ **英文标签版，已废弃**。它按供应商聚合金额会笛卡尔积（单个供应商虚高 24 倍）。**别跑** |
| — | `提数据_编JSONL.py` | 小样版：取 10 条编成 `batch_requests_10.jsonl` |

`batch/结果/` 里是这条链路的中间产物（含**真实单位名与金额**，已 gitignore）。

## 9. 「我改了这个，该跑什么」

这是本文件最实用的一张表。**改任何一处，先在这里找对应行。**

| 改了什么 | 跑什么 | 需要服务吗 |
| --- | --- | --- |
| 检索层（`retriever` / `hybrid` / `reranker` / 阈值） | `scripts/eval_rag.py --no-llm` | 否（但要停后端） |
| 提示词（`rag.py`） | `scripts/eval_rag.py --limit 5` | 需 API Key |
| Agent 循环（`agent.py`） | `eval/agent_eval.py --selftest` → `--limit 3` | 前者否，后者需全服务 |
| 工具层（`tools/`） | `probe_recover.py` + `probe_quality.py` + `probe_tools.py` | 前两个否 |
| 图谱（`graph_store.py` 或任何 Cypher） | `probe_graph_store.py` | 需 Neo4j |
| 采购库（`pg_store.py` 或任何 SQL） | `probe_pg_store.py` | 需 PostgreSQL |
| 对话历史 / 反馈（`conv_store.py` 或任何 SQL） | `probe_conv_store.py` + `probe_feedback.py` | 需 PostgreSQL |
| 联网（`web_search.py`） | `probe_web_search.py` | 离线段不需要 |
| Exa / MCP | `probe_web_search.py` ⑧ + `probe_mcp_server.py` | 离线段不需要 |
| 供应商（`clients/`） | `probe_llm_provider.py` | 否 |
| 配置字段（`config.py`） | `probe_config.py` | 否 |
| 限流（`api.py` 那三行） | `probe_rate_limit.py` | 否 |
| 图片解析（`clients/vision_client.py`） | `probe_vision.py` | 离线 + 真机 |
| 前端 | `npm run build`（先停 dev server） | 否 |
| 数据入库 | `python -m bidding_qa.ingest --recreate` | 否（但**必须停后端**） |
