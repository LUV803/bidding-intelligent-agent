## 工具层（`bidding_qa/tools/`）

这些工具的**定义**（schema / 参数模型 / 处理器 / 展示 / 归属判定）原先全挤在 `agent.py` 里，
2026-09-20 抽成独立的包，并改为 **Pydantic 模型驱动**：

```
src/bidding_qa/tools/
├─ base.py        引擎：BaseTool / 注册表 / execute_tool / recover_tool_calls / SourceRegistry
│                 schema 生成（to_openai_schema）+ 清洗层 + 宽容取整（tolerant_int）
└─ rag_tools.py   四个具体工具 + TOOL_* 常量 + TOOL_SCHEMAS / TOOL_NAMES / tools_for / web_lookup
```

⚠ **不是 `src/tools/`**。`pyproject.toml` 的 `[tool.uv.build-backend] module-name = "bidding_qa"`
只声明这一个包，`src/tools/` 现在能 import 全靠可编辑安装的 `.pth`，非可编辑安装时整个消失。

**依赖方向是唯一的硬约束**：`tools/*` 可以 import `..config` / `..schemas` / `..clients` /
`..graph_store` / `..pg_store` / `..web_search` / `..rag`，但**绝不 import `..agent`**
（`agent.py` 是上层，反过来立刻成环）。⚠ 2026-09-30 起多一条同方向的边：
`..mcp.mcp_bridge`（三个 `run()` 里的 MCP 路由分支）；⚠ 反过来 —— `mcp/` 下**绝不 import
`..tools`**，理由与故障形态见「自建 MCP 服务器」一节。能力模块 `graph_store.py` / `pg_store.py` /
`web_search.py` / `retriever.py` **留在原地**——本次只搬工具定义层。

⚠ **图谱 / 采购库 / 技能三个 `run()` 里现在多了一个路由分支**（
`if mcp_bridge.is_enabled(): … return outcome_from_payload(payload)`，见「自建 MCP 服务器」）。
它的位置是**校验与去重之后**、本地调用之前 —— ⚠ 别把它提到 `execute_tool` 上去
（那会把 `ctx.seen` 的键**提前**写进去，模型第一次参数写错就再也改不对了，理由见那一节）。
其余三个工具（检索 + 两个联网）**没有**这个分支：它们各自持有 retriever / 是每请求挂的。

### ⚠⚠ 清洗层：Pydantic 的天然产出会**静默**弄坏恢复机制

这是整件事最大的技术地雷。`_normalize_args()` 直接读**裸 JSON Schema 键**
（`.get("type") == "integer"`），而 `model_json_schema()` 对 `int | None` 的产出是
`anyOf: [{type:integer,…},{type:null}]` —— **没有顶层 `type`**。`.get` 返回 `None`，
于是掉进 `else` 分支**把原值原样收下**：恢复路径传进来的是从标记里抠出来的**字符串**，
一次 `top_k="5"` 的恢复会变成字符串 `"5"` 交给 handler。**不报错、不崩溃，只是类型变了。**

⇒ `to_openai_schema()` 生成后必须过一层清洗（`_clean_property` / `_drop_noise`）：
剥掉每个属性的 `title`（Pydantic 把 `top_k` 转成英文标题，纯噪声）与 `default: null`，
把 `anyOf` 里**非 null 的那个分支提回顶层**（保住 `default`/`description`）。
⚠ **多分支的 `anyOf` 要原样保留**，别一律展平 —— `float | str` 展平后就没有任何类型信息了，
而那条 `anyOf: [{type:number},{type:string}]` 恰恰是告诉模型「`"50万"` 与 `50000` 都行」的载体。

⚠ 配套的**类型约定**（`rag_tools.py` 里每个字段都靠它）：

| 字段 | 写法 | 为什么 |
| --- | --- | --- |
| 文本参数 | `str \| None = Field(default=None, description=…)` | 正常走 Pydantic |
| `top_k` / `max_rows` / `max_results` | `Any` + `json_schema_extra={"type":"integer","minimum":…,"maximum":…}` | 见下 |
| `amount_min` / `amount_max` / `sort_desc` | `Any` + `{"type":"number"}` / `{"type":"boolean"}` | 原样透传给 `pg_store` 解析 |
| 枚举（`query_type` / `sort_by` / `group_by` / `date_field`） | `str \| None` + `json_schema_extra={"enum": […]}` | **刻意不用 `Literal[...]`** |

**刻意不用精确类型**，两条理由都是「别把标定好的容错换成一句通用报错」：
① 用 `int` + `ge`/`le` 会让「`top_k=50` 夹紧到 `agent_tool_max_top_k`」变成
`ValidationError`；② 用 `Literal[...]` 会让 `graph_store` 那句**带可用值列表的**中文报错
（「错误：没有名为 X 的查询类型。可用类型：…」）变成 Pydantic 的英文枚举报错。
schema 里**照样**有 `enum` / `minimum` / `maximum`（模型与 `_normalize_args` 都看得到），
只是经由 `json_schema_extra` 声明。
⚠ `description` 里那些**中文逐值说明**（`"；".join(f"{k}={v}" …QUERY_TYPE_LABELS…)`）
必须保留 —— 那是模型选对枚举值的唯一依据。

### 注册 ≠ 挂出去

`base.py` 持一个模块级注册表：每个 `BaseTool` 在 import 期 `register()` 一次
（**六个工具全部无条件注册**，引擎知道所有处理器）；`TOOL_SCHEMAS` 是**挂出去**的那份，
按 `graph_store.ENABLED` / `pg_store.ENABLED` 过滤。两者的差别有意义：被禁用的工具
若真被调用，拿到的是**该工具自己如实的失败**，而不是「没有这个工具」。

⚠ `recover_tool_calls()` / `_match_schema()` 的 `schemas` 默认值取的是**进程级那批**
（= `TOOL_SCHEMAS`），**不是本轮挂出去的那批** —— 两者差着 `search_web`，所以
`run_agent_stream` 必须把本轮的 `tools` 显式传下去（那条 ⚠⚠ 在「Agent 模式」里）。
而 `base` **不能** `from .rag_tools import TOOL_SCHEMAS`（那是 base→rag_tools，而成环）。
解法是 `rag_tools` 在 import 期 `set_default_pool(lambda: TOOL_SCHEMAS)` 把**取值方式**交出去。
⚠ **必须是 lambda 不是快照**：`tools_for()` 是**调用期**读全局，`eval_rag --pipeline agent`
靠替换 `rag_tools.TOOL_SCHEMAS` 摘工具（见「RAG 质量评估」），快照会让那次替换失效。
⚠ `tools/__init__.py` **必须把两个子模块都拉进来** —— 只 import `base` 的话那个池是空的，
`recover_tool_calls()` 会把一切泄漏标记判成「判不出归属」而丢掉。那是个**安全的**降级形态
（不抛异常），所以漏了也看不出错，只会静默失效。

### ⚠⚠ 结果质量检查：空手而归时**追加**一句下一步（2026-09-20 加）

`base.assess_outcome()` 由 `run_agent_stream()` 在把 `role:"tool"` 消息塞进对话**之前**
调用一次，不达标就**追加**一段提示到 `outcome.text` **之后**：

```
【结果质量】本次调用没有拿到任何结果（库里匹配到 0 行）。
本轮还挂着这些工具，这个问题若更适合它们请改调：search_bidding_knowledge（法规条文…）；
search_knowledge_graph（某企业/某类标的物的交易记录…）。
也可以换个更精确的参数或表述再调一次同一个工具（别用一模一样的参数）；
若都不适用，就如实告诉用户「没有查到」，不要用常识或推测补足。
```

⚠⚠ **判据一律是结构性的**（行数 / 条数），**刻意不用相似度分数**。需求原文写的是
「检查结果质量（行数、**相关性分数**）」，但后半截在这个仓库里**做不到**：向量分对
「答非所问」恰恰没有区分力 —— 实测完全不相干的资料得 **0.8166**，在
`MIN_VECTOR_SCORE=0.72` **之上**（盐化工那次，见「Agent 模式」）。唯一能判「这份资料
能不能回答」的信号是 CrossEncoder 的重排分（能答 ≈0.73 / 答不了 ≈0.50），但它**只在
重排开启时存在**，而重排是用户可随时关掉的前端开关 —— 拿它当闸门等于「关了重排就没有
质量检查」。所以 `empty_reason()` 只认「拿到了几条」这件**不依赖任何标定**的事实。

⚠⚠ **本机制只做「告知 + 把选项摆到眼前」，不替模型做决定** —— 这是它与「自动换工具」
的分界，别照着需求原文把它加强成后者。系统无从判断「数据库答不了但图谱能答」，那要
理解问题语义；所以它做的是**点名本轮还挂着的其他工具**（让路由选项变显眼），再**允许**
模型如实说「没查到」。这与「`/api/chat` 答不出就自动联网」那套被整块删除是**同一条
纪律**：那条死于**服务端替模型做语义判断**必然静默出错（旧触发 ③ 死于话术判据）。

五条设计约束，缺一条都会静默坏掉：

1. **只追加，不替换**。`outcome.text` 是 `_render_result()` 的产出，字面量被
   `probe_web_search.py` ⑥ 钉着；结果合格时 `assess_outcome()` 返回 `None`，**连分隔符
   都不多一个**（非空路径逐字节不变）。⚠ 写成替换的话，`probe_web_search.py` 会红，
   **但那条红指向「web 的字面量变了」，指向不到真正的原因** —— 所以 `probe_quality.py` ⑤
   在最靠近故障点的地方自己又钉了一遍逐字节相等。
2. **只点名本轮真挂着的工具**（`ctx.tool_names`，不是进程级的 `TOOL_SCHEMAS`）。联网关着
   时提 `search_web` 就是让模型去调一个本轮没挂出去的工具 —— 与 `rag.py` 里
   `_AGENT_DB_CROSS_TOOL_RULE`「只在图谱与数据库都启用时才拼进去」是同一条纪律。
   ⚠ 只剩**一个**工具时**不提**「改调」那句（无人可换），但仍保留「如实说没查到」。
3. **参数写错时不插话**（`_SELF_CORRECTING_ERRORS`）。`unknown_tool` / `bad_arguments` /
   `bad_query_type` / `empty_query` / `duplicate_query` 各自的文案**本身就带修正线索**
   （「可用工具：…」「可用类型：…」），再叠一段「换个工具」只会把「把参数改对」这条
   更重要的指令淹掉。⚠ 加新 error 码时想清楚：只有「模型知道怎么改」的才放进来；
   **真正的失败（连接超时、handler 崩溃）必须走提示** —— 那才是该换工具或如实说明的时候。
4. **判据取 `total` 而不是 `len(rows)`**（图谱/数据库）。`rows` 是按 `graph_max_rows` /
   `pg_max_rows` 截断后的明细，**截断成空不代表没命中**。`empty_reason()` 由各工具覆写：
   检索与联网用基类默认（`new_sources` / `known_indices` 双双为空），图谱与数据库读自己
   那份 `total`，`ok=False` 时回 `note` 原文。
5. ⚠⚠ **「找到了但被来源额度丢掉」不是空手而归**（2026-09-20 修，与轮数/来源上限一起）。
   `SourceRegistry` 撞顶时 `fresh` / `known` 双双为空，与「真的一条没命中」**形状一模一样**。
   原先有两个地方把它读成了后者：
   - `_render_result` 里那句 `（另有 N 条超出本次来源上限）` 写在 `if not fresh:` 的
     **`return` 之后**，撞顶时**永远执行不到**，模型只看到「没有新增资料」；
   - `empty_reason()` 看不到任何区别，于是 `assess_outcome()` 在**紧接着的下一行**说
     「本次调用没有拿到任何结果…可以如实告诉用户没有查到」——两句直接打架，
     而模型会照后一句把一次**命中**说成**知识库没有**。
   ⇒ `ToolOutcome` 加了 `dropped` 字段（两个检索工具在 `registry.add()` 处填），
   `_render_result` 为它单开一支（「匹配到 N 条，但本次来源额度已满，均未提供」+
   **禁止**模型断言知识库没有），`empty_reason()` 把它与另两个信号并列。
   ⚠ `dropped == 0` 那两支**必须逐字节等于改动前**（`probe_web_search.py` ⑥ 钉着字面量），
   `probe_quality.py` ⑥ 在最近处又钉了一遍。**加轮数/加工具都会推高撞顶概率**，
   动这两个常量时先看这一条。

⚠ `route_label` 是每个工具给提示用的**一句话短标签**（「法规条文、政策口径、办事流程」），
**别把 `description` 抄一遍** —— 那段有十几行，抄进去会把上下文预算吃掉一大块。
`probe_quality.py` ④ 逐个断言六个工具都配了它（⚠ 那张名单是**手写的**，加新工具时要记得加名字 —— 加 Exa 时就漏过一次）。

### ⚠⚠ `agent.py` 的 re-export 是**只读**的

`api.py` 与十几个探针都按 `agent.XXX` 取用（`SourceRegistry` / `ToolContext` / `TOOL_*` /
`tools_for` / `execute_tool` / `_peek_display` / `_HANDLERS` …），所以 `agent.py` 保留了
一整套转发，**下划线名也要显式列出**（`from .tools import *` 会跳过它们）。

⚠ **转发只对读有效**：`agent.TOOL_SCHEMAS = [...]` 只是给 `agent` 的命名空间加了个新名字，
`tools_for()` 读的仍是 `rag_tools` 的全局。要换工具表就写 **`rag_tools.TOOL_SCHEMAS`**
—— `eval_rag._isolate_agent_tools()` 就是那么干的（写错会**静默失效**：三个可选工具照旧挂着，
报告的上下文里混进图谱行与网页正文，而四项指标看起来一切正常）。

⚠ `_HANDLERS` 这个名字必须保住（`probe_pg_store.py:101` 钉着 `agent.TOOL_PG in agent._HANDLERS`），
它由注册表派生、与 `register()` 一起维护，`agent.py import` 期有一条 `assert` 挡住两边漂移。
⚠⚠ **它与 `graph_store._HANDLERS` 同名但不是一回事**（纯属巧合）：那张是「**查询类型** →
一段 Cypher」（`graph_store.py:609`，键是 `e_related` 那些），这张是「**工具名** → 工具执行体」。
两者都只用模块限定访问（`graph_store._HANDLERS` / `agent._HANDLERS`），不会串；
但读代码时别把 `probe_graph_store.py` 里那条 `assert set(_HANDLERS) == set(QUERY_TYPE_LABELS)`
当成对工具表的断言 —— 它守的是图谱那 9 个查询类型。

### 探针的「假名」约定（**别顺手改成新名**）

`probe_recover.py` / `probe_recover_e2e.py` / `probe_web_search.py` 里，「模型吐出一个
**不存在的**工具名」这类夹具**一律用改名前的旧名**（`query_knowledge_graph` 等）：
它们既不存在、又长得极像真名，正是模型会真吐出来的形状。

⚠⚠ **为什么不能用真名**：`_schema_by_name()` 是**精确相等**查表，名字一旦命中注册表，
归属就走「名字优先」，**参数投票整段不执行**。若把夹具名换成一个真名，那些靠
「名字对不上 → 退回投票」的用例会**静默切换路径、断言照样全绿，覆盖却没了**
（2026-09-20 改名时 `search_knowledge_graph` 正好从幻觉名变成了真名，就是这么踩到的）。
`probe_recover.py` 用例 0b 因此逐名断言「这些夹具确实没注册」—— 那几条是
「用例 1 / 反向 ③ 究竟测的是哪条路径」的**唯一凭证**。
反过来，要验「名字精确命中」的用例（用例 2 / 3c / 反向 ①②）夹具**必须**是真名。

### 其余几条

- **`_peek_display()` 收进了 `BaseTool.peek_display()`** —— 基类默认读 `query` 字段
  （只有检索工具用得上），图谱/采购库/联网三个各自覆写；`_peek_display(name, arguments)`
  那个模块级函数**保留原签名**（`probe_pg_tool.py` 当场调它），只是改成查注册表后转发。
  「新增工具忘了加展示分支 → 界面显示一对空的『』」这个坑从机制上消失了。
- **`_HANDLERS` / `execute_tool` 的调度不变**，三个不变量（工具执行永不抛异常 / 循环必定收口 /
  引用编号全局唯一）原样 —— `SourceRegistry` 是**逐字**搬过来的。
- **恢复机制的算法一个字没改**：`_match_schema` 的多数决、「对不上就整条丢弃」、
  `_schema_by_name` 的「精确相等、禁止归一化」全是原样搬迁，只是换了名字的来源。
- ⚠ **`_PARAM_ALIASES` 与「名字限定的别名表」仍分开放**，**不能并进全局表** ——
  `query` 已被 `search_bidding_knowledge` 占了，全局改写成 `web_query` 会让一次**检索**的
  泄漏从「稳赢」变成打平（0:0）→ 整条丢弃。区别是它现在挂在**工具类**上
  （`WebSearchTool.name_scoped_aliases = {"query": "web_query"}`），`_bind_params()`
  经 `_REGISTRY.get(name)` 取 —— **原先是模块级 dict + 裸工具名字面量做键**，改名时那是个
  静默失效点（别名落空 → 一次联网泄漏被投票判给检索工具），挂到类上就跟着名字一起走。
  ⚠ 但 `named is not None` 那道**闸必须保留**：它保证「本轮没挂的工具不享受名字限定别名」，
  `probe_web_search.py` ⑧ 钉着「不传本轮工具表时 `search_web` 的泄漏必须恢复不出来」。
