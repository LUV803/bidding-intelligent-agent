# 限流与启动配置体检

> `CLAUDE.md` 拆出来的深潜正文（原「限流」「启动配置体检」两节）。
> 改 `api.py` 的 Limiter 接线 / `config.py` 的 Settings 字段之前，先把这里读完。

## 限流（slowapi，2026-09-21 加）

`api.py` 里三行：`Limiter` + `RateLimitExceeded` 处理器 + `SlowAPIMiddleware`。
开关是 `settings.rate_limit_per_minute`（**0 = 关掉**，此时连中间件都不挂）。

⚠⚠ **桶是「每个端点」的，不是全站合计** —— 这条**最容易记错**（我第一版注释就写错了）。
slowapi 的桶键是 `(key_func() 的结果, 端点函数名)`（`extension.py:570` 的 `_endpoint_key`
默认取 `f"{模块名}.{函数名}"`，除非 `key_style="url"` 才按路径分）。所以是
**`/api/chat` 120/分钟、`/api/agent` 另有 120/分钟**，不是两边加起来 120。
真机验过：把 `/api/search` 打满 429 之后，`/api/config` 照样 200。

⚠⚠ **429 处理器必须写成同步的 `def`**（`_rate_limited`）。`SlowAPIMiddleware` 走的是
slowapi 的 `sync_check_limits`，那里对**协程**处理器会**静默**退回它自带的英文
`_rate_limit_exceeded_handler` —— 不报错、不抛异常，只是用户读到一句英文。
`probe_rate_limit.py` ① 用 `iscoroutinefunction` 钉着。

⚠ `Retry-After: 60` 是 **api.py 自己补的**，slowapi 在这条路径上**不注入任何限流响应头**
（`sync_check_limits` 在出错分支返回 `should_inject_headers=False`），不写就是光秃秃一个 429。

⚠⚠ **别换成 `SlowAPIASGIMiddleware`**（纯 ASGI 那个，看着更"正确"）。它的 `send_wrapper`
每收到一个 `http.response.body` 就**重发一次 `http.response.start`** —— 只对「一个 body
就结束」的普通响应成立，而本服务三条问答链路全是 SSE（几百上千个分片），重发 start 是
**ASGI 协议违例**。① 有一条断言专门挡这个。

⚠ **`/api/health` 整个豁免**（`@limiter.exempt`）。不是洁癖：前端轮询间隔是
`health?.status === "ok" ? 30000 : 4000`，健康检查一旦被 429，`status` 就不再是 `ok`，
前端会把轮询**加快到每 4 秒一次**——正好去撞更紧的限流，是个**正反馈**。它也是整个服务里
最便宜的端点（不调大模型、不碰外部 API）。

⚠ 豁免是靠**端点函数名**匹配的（`_get_route_name` = `模块名.函数名`）。health 改模块或改名
会**静默**失去豁免，① 里有一条「路由上那个端点的名字逐字对得上」挡着。

⚠ 限额值定成 **120 而不是 30**，唯一原因是 `scripts/eval_rag.py --retrieval http/auto`
会从 127.0.0.1 连着打 74 个 `/api/search`（`--no-llm` 下几秒内打完）——**同一个端点**，
所以按端点的桶照样会卡住它。好在 `eval_rag.py:820` 有 `response.raise_for_status()`，
是**响的**失败不是静默降级。改这个值之前先想一下那条链路。
⚠ 前端没有任何路径会撞上：`/api/health` 豁免，其余每个端点每轮提问最多一两次。

⚠⚠ **限流挡不住真正的暴露面** —— `API_HOST` 默认 `0.0.0.0`（绑定所有网卡），
而本服务**没有任何认证**。局域网内任何机器都能直接问，而 `web_search` 是**请求参数**，
所以隔壁那台机器上的人可以白白烧掉 Tavily 额度。**CORS 拦不住这个**（它是浏览器规则，
`curl` / 脚本不理会）。只在本机用就把 `.env` 的 `API_HOST` 改成 `127.0.0.1`——
那是比限流正确的修法，也是**一行**。要拿手机/另一台电脑演示才需要留 `0.0.0.0`。

改 `api.py` 那三行接线 / `config.py` 的 `rate_limit_per_minute` 之后跑：

```bash
uv run python scripts/probe_rate_limit.py   # 25 条，**全离线**（需要 fastapi.testclient，已是依赖）
```

⚠ 这个探针**必须在 `import bidding_qa.api` 之前**改 `settings.rate_limit_per_minute`：
限额是 `api.py` 的模块级 `_limits`，import 期算一次就定死了。⑤ 验「0 = 关闭」时靠
`importlib.reload(api)` 重算。

⚠ **没能在这里钉住的**：`BaseHTTPMiddleware` 会不会把整条流**缓冲**到最后才吐。
`TestClient` 是进程内 ASGI，一个「攒完再放」的中间件在那儿看起来与真流式一模一样。
所以 ④ 只钉「事件序列完整」，**别把它当成流式性的凭证** —— 那条只能真机验
（实测一次 `/api/agent`：`start` 0.02s → `sources` 1.27s → `reasoning` 1.71s（79 个分片）
→ `delta` 3.03s，确实是边生成边到）。

## 启动配置体检（`config.py`，2026-09-21 加）

`Settings` 上挂了一个 `model_validator(mode="after")`（`_report_startup_config`），在
**`Settings()` 构造时**把配置一次说清 —— 也就是 `config.py` 末尾那句模块级
`settings = get_settings()`，**import 期**就跑完，早于一切。

它回答一个此前**没有任何地方回答**的问题：「这台机器上，哪些可选能力没开、为什么」。

> ⚠ 先纠正一个流传的前提：**本仓库从来没有 `settings.validate()`**。
> `Settings.validate` 是 pydantic 的 `BaseModel.validate(value)` —— 校验**单个值**的
> classmethod，跟配置完整性毫无关系（`probe_config.py` ① 有一条断言把这个误会钉在案）。
> 所以「缺失项」原先根本没有集中检查点，这个校验器就是补上的那一个。

### ⚠⚠ 只念不拦：**绝不 `raise`**

这是本节最要紧的一条，也是最容易被「顺手加强」掉的一条。五个可选能力全靠
「没配就降级」活着（`graph_store.ENABLED` / `pg_store.ENABLED` / `web_search.ENABLED` /
**`web_search_exa.ENABLED`** / `vision` 全是 `bool(settings.X.strip())`），
而 **`.env.example` 交上去时这几个 Key 本来就是空的**。
在那里 `raise` 等于「谁都没配 Key 就起不来服务」—— 把「可选」变成「必需」，
与整套设计直接冲突，也和 `/api/health` 那套「如实报告」的既有做法背道而驰。
**体检的价值在于说清楚，不在于拦住。**

### 它报三件事

1. **没启用的可选能力**（逐项点名 + 缺哪个 Key + 会失去什么）——
   数据来自 `_OPTIONAL_CAPS`（`config.py` 模块级那张表）。
2. **两个文本大模型 Key 都是空的** ⇒ 会退化成 `fallback_answer`。
   ⚠ 判据刻意用**两个 Key 的合取**，**不按 provider→key 映射判**：那个映射在
   `clients/llm_factory.py`，而 `config.py` 反向 import clients 会**立刻成环**
   （clients 全都 `from ..config import settings`），照抄一份则是本仓库反复记过的
   「加第三家供应商要改四处」。合取是这里能拿到的最强信号，且不会随供应商增减而漂移。
3. ⚠⚠ **`.env` 里未声明的键**（`_undeclared_env_keys()`）—— **这是本条最值钱的部分**。
   `extra="ignore"` 会把 `config.py` 没有同名字段的键**静默丢弃**，本仓库为此栽过
   **四次**（Neo4j / Postgres / Zhipu / Tavily），症状一律是「`.env` 里明明写了，代码就是
   读不到」，不报错、不警告，往往隔着几周才发现。现在启动时逐个点名。
   ⚠ 只查**这个方向**。反方向（字段有、`.env` 没写）是**正常状态** —— 83 个字段绝大多数
   靠默认值，逐个报会变成一屏噪声，而噪声里的真警报没人看。
   ⚠ 比对是**大小写不敏感**的（`case_sensitive=False`），`export KEY=` 前缀与前后空格都处理。

### ⚠ 三条实现约束

- **级别必须是 WARNING，别降成 INFO**。它跑在**任何 `logging.basicConfig` 之前**
  （`config.py` 是 import 期，`api.py:49` 的 basicConfig 还没执行），那时只有 WARNING 能经
  `logging.lastResort` 落到 stderr，**INFO 会被直接丢弃** —— 体检就白做了。
  代价是这几行**没有时间戳**、格式光秃秃地排在所有带格式的日志**前面**。这是**故意的**：
  早于一切、绝不漏掉。
  ⚠ 所以也**别把它挪进 `_bootstrap()`** 图个格式好看 —— 那样 `scripts/*.py` 与
  `batch/*.py` 这些不跑 bootstrap 的入口就再也体检不到了。
- ⚠⚠ **`mode="after"`，且只在构造时跑一次**。`probe_llm_provider.py` / `probe_rate_limit.py`
  都靠在**运行期给 `settings` 属性赋值**来改行为（`settings.rate_limit_per_minute = 3`），
  属性赋值**不会**重新触发校验器。改成 `validate_assignment` 或把逻辑挪进 `__setattr__`
  会让那些探针集体噪起来。⑤ 钉着这条。
- ⚠ **`_OPTIONAL_CAPS` 里的字段名必须都在 `Settings.model_fields` 里**：改名/删字段而漏改
  这张表的话，`getattr(s, field, "")` 会静默拿到哨兵 `""`，于是一个**开着**的能力被报成
  「未启用」—— 又一个「看起来完全合理的错误答案」。① 有一条断言挡这个。
  ⚠ 加一个可选能力 = **在 `_OPTIONAL_CAPS` 里加一行**（前提是它的开关就是本类里某个字段非空）。
  ⚠ `zhipu_api_key` **身兼两职**（图片解析的开关 + `LLM_PROVIDER=zai` 时的文本 Key），
  所以它空着时只报「图片解析不可用」并不全面；真要用的那家没 Key 会在**回答里**如实点名
  （`rag._no_key_hint()`），这里不重复。
  ⚠⚠ **标签有一条「不得互为前后缀」的隐含约束**（2026-09-30 加 Exa 时踩到）：
  「联网搜索」正是「Exa 联网搜索」的后半截，而探针原先按 `label in line` 断言 —— 于是
  「关掉 Exa」那一格**假红**（匹配到的其实是 Tavily 那一项）。探针侧的判据因此收紧成
  `_cap_hits()`（要求 `：{label}：` 或 `；{label}：`，即标签**整体**出现）。
  ⚠ 但 `config.py` 这一侧**没有跟着改** —— 那是**有意的**：标签带「Exa」前缀正是为了让人
  一眼看出是哪个能力，而「谁是另一个的前缀」靠判据挡比靠起名挡更可靠（起名约束没有机制守着）。
  ⇒ **加新能力时起个不互为前缀的标签更好，但别为此改名**（改名会连带 `_cap_hits` 的调用点）。

> ✅ **配置齐备的机器上它一行都不输出**（本机当前 `.env` 就是 0 行）。这是刻意的：
> 刷一屏「一切正常」的日志等于把体检变成噪声。只有真缺东西时才说话。
