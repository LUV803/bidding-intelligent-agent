# 前端要点

- 配色走 `globals.css` 里的 CSS 变量（RGB 三元组），Tailwind 在 `tailwind.config.ts` 里映射成 `bg-canvas`/`text-ink`/`bg-brand` 等语义色名，`darkMode: 'class'`。加颜色请沿用这套变量，不要硬编码 hex。
- **行内引用 `[n]` 的渲染技巧**：`Markdown.tsx` 先用正则把 `[n]` 转成 Markdown 链接 `[n](#cite-n)`，再在 `a` 组件渲染器里识别 `#cite-` 前缀替换成角标按钮。比操作 AST 简单，且不会误伤真实的 `[text](url)`。
- **所有会话状态集中在 `hooks/useChat.ts`**（含 localStorage 持久化、流式中止、重新生成）。流式消费用 `AbortController`，`page.tsx` 只负责布局与主题。
- 来源面板的展开状态由 `ChatMessage` 持有并向下传（受控），这样点击正文角标能联动展开并滚动定位。
- **底部控件的 prop 要一路传到底**：`hybrid` / `rerank` / `webSearch` / `llmProvider` 都从 `useChat` 出发，经 `page.tsx` → `WelcomeScreen` / `ChatInput`。新增开关时这几条路径（`page.tsx` 有**两条**，首屏那条和多轮那条）都要改，否则首屏（WelcomeScreen）和多轮对话（ChatInput）行为不一致。
  ⚠ 原先第 4 个是 `agent`（「Agent 模式」开关），2026-09-20 删了——见「项目概览」；
  2026-09-21 补上的 `llmProvider` 是**同一个位置上的新 occupant**，与它没有沿革关系。
  ⚠ `llmProvider` 与那三个 bool 开关**形状不同**，照抄时容易只抄一半：它是**字符串**
  （`""` = 跟服务端默认），且配套要三个**不是开关**的 prop 一起走同一条路径 ——
  `llmDefaultProvider`（`health.llm_provider`）/ `llmProviders`（`health.llm_providers`）/
  `onSelectLlmProvider`（`chat.setLlmProvider`）。⚠ **`onSelectLlmProvider` 是四个 prop 里
  唯一的函数** —— 漏传它的表现是「胶囊点下去毫无反应」（`ChatInput` 里那次 `cycleLlm()` 调了个
  `undefined`，React 直接抛，整页白屏），比另外三个漏传都响。
  ⚠ 同一组路径上还走着一个**不是开关**的 prop：`webConfigured`（`page.tsx` 从 `health` 取，不经过 `useChat`），用途见 `联网搜索与Exa.md`。它同样要喂两个 `ChatInput`——**漏掉 WelcomeScreen 那条的表现是「首屏开关没有提示，多轮界面上有」**。
- **`useChat.ts` 的 `run()` 依赖数组**别漏掉开关：`[hybrid, rerank, webSearch, llmProvider, patchMessage]`。漏了会拿到闭包里的旧值，表现为「开关点了但没生效」。
  ⚠ `llmProvider` 漏在这一处**表现最不直观**：胶囊上显示的字是**对的**（它从 prop 拿），
  但发出去的请求里带的是**切换前那家** —— 界面说自己切了、实际没切。
- **开关状态存 localStorage 的 hydrate / persist 是两处**（读的地方在挂载 effect 里，写的地方各一个 effect），漏掉任何一个的表现都是「刷新后回默认值」。
  ⚠ 现在**持久化的有三个**：`hybrid` / `rerank` / **`llmProvider`**（键
  `bidding-qa-llm-provider`，2026-09-21 加）。⚠ 它的 persist effect **空串也要写**：
  不写的话上次选过的 GLM 会一直留在 localStorage 里，「切回服务端默认」这个动作就存不下来，
  刷新后又被读回来。
  ⚠ 剩下两个**不持久化**：`agent`（开关整个删了）与 **`webSearch`**
  （刻意不持久化，理由见「联网搜索 → 前端」）都**只留下了没人读的旧键**，别再给它们补 hydrate。
  ⚠ 删 `agent` 开关时**只删了读和写，没删那个键**：`bidding-qa-agent=false` 可能还躺在老用户的
  localStorage 里。**别顺手把它读回来「兼容」**——读回来会让那部分用户被**永久钉在写死流水线上**
  （开关已经没了，他再也拨不回来），且界面上完全看不出异常。让它烂着就对了。
  `bidding-qa-web-search` 是**同一条处置的镜像**：那边残留的 `true` 会把联网搜索永久粘在开启态，
  一样烂着别读。
- **`ChatInput` 底部工具条在正常文档流里**（不是绝对定位），容器的 `pb-2.5` 与工具条的 `mt-0.5` 是一对，**别单独动其中一个**：开关多到一定程度后窄屏（375px）会换行，而绝对定位是从底部向上长的，换行后会盖住 textarea 最后一行。改成流式布局后总高与原来一致，窄屏换行时容器自然变高。（现在工具条上是三个开关 + LLM 胶囊 + 附件 + 联网。）
- **底部控件的尺寸与样式有一条统一约定**（2026-09-20 改成 OpenAI 风格时定的）：五个控件
  **一律 `h-8`**（回形针 `h-8 w-8`、四个胶囊 `h-8 px-3 text-[12.5px]`、发送/停止 `h-8 w-8`），
  胶囊**不带描边**，靠 `bg-hover`（关）/ `bg-brand-soft text-brand`（开）的深浅区分开关态。
  参差不齐（28/26/32）正是改版之前的样子，**改高度要五个一起改**。
  ⚠ LLM 胶囊（2026-09-21 加）有**第三种态**：**整个不渲染**。可选供应商 < 2 时没有可选项，
  不摆一个点不动的死按钮。它和另外三个的**亮/暗判据也不同** —— 那三个照自己的 bool，
  它照 `llmProvider !== ""`（**选了**才亮，跟服务端默认时是暗的）。
  ⚠ 同时**别给这个容器加 `focus-within:ring-*`**：Tailwind v3 的 ring 靠 `--tw-ring-shadow`
  参与 `box-shadow` 合成，而容器的阴影是**任意值** `shadow-[…]`（不走合成变量），
  两者同时写 ring 会被整条盖掉、**静默不显示**。焦距态只用 `focus-within:border-brand/60`。
  ⚠ 容器的 `dark:shadow-[…]` 不是装饰：原来的 `rgba(0,0,0,0.04)` 在暗底上完全看不见，
  是那次改版顺带修的既有问题。
- **首屏「图谱/数据库」示例卡片现在不需要任何 override 了**（2026-09-20 简化）。原先它得一边
  `onToggleAgent(true)` 一边带 `{ agent: true }` 发送——不带 override 的话这次请求会打到
  `/api/chat`（图谱工具压根没注册），表现是「点了卡片却答不出来」。整条链路固定走 `/api/agent`
  之后，`WelcomeScreen.pick()` 就是一句 `onSend(item.title)`。
  ⚠ **`run()` 的 `overrides` 形参仍然删不得**——附件（`overrides.image`）还在用它绕开
  setState 的闭包竞态。只是 `SendOverrides.agent` 那个字段没了。
  ⚠ 新增「需要工具」的卡片时 `blockedBy()`、`blockReason()` 仍各要加一处（工具不可用时如实置灰）；网格奇偶也要顺带看一眼（末尾那张 `wide` 卡是拿来收尾的）。
  ⚠ **要恢复「直接 RAG / Agent 模式」切换**：`lib/api.ts` 按参数分派端点 → `useChat` 加回状态与
  localStorage → `WelcomeScreen.pick()` 恢复 override → 工具条加回按钮。四处缺一不可，
  少任何一处都是「点了卡片答不出来」或「开关点了不生效」这种静默故障。
- 重排开关只影响「下一次提问」，不会重跑已有消息——所以来源卡片里的重排得分/位次升降是按消息存的，不在前端做换算。
- **工具结果的呈现分三层**：`ToolCallBlock` 只画「调了什么、成没成」的摘要行（工具名/运行中文案全在它那张 `TOOLS` 表里，**一处漏改总好过三处**）；图谱结果由 `GraphResultBlock` 独立成块、采购记录由 `PgResultBlock` 独立成块，`ChatMessage` 遍历 `steps` 依次取 `step.graph` / `step.pg` 渲染。这两个块都**刻意不接 `SourcePanel`**——来源面板是带 `[n]` 编号的问答对，会被正文角标联动，图谱与数据库行是结构化结果，混在一起会让人以为那些行也是「资料」。
- `PgResultBlock` 顶部把 `filters` 显式渲染出来（「筛选：省份=安徽省，中标金额≥…」）**是这个块的主要价值**：模型把「安徽」理解成省份筛选、把「过亿」理解成金额下限，这些理解偏差不摆出来的话，一个答非所问的结果看起来和正确的完全一样。表格列按 `mode`（detail/group）分流，不是按「哪些字段非空」——两种模式的行形状没有交集。
- `useChat.ts` 消费事件的 `else if` 链**没有 default 分支也不做穷尽检查**：新增事件类型或事件字段时漏了，不报错，只是「事件到了但什么都不显示」。同理 `newCount` 那个守卫要记得把**所有非检索工具**都列上（漏一个，那个工具的步骤就会显示成「新增 0 条资料」——一个看起来合理但完全错误的说法）。
- **附件（图片）走的是三处联动的链路**，漏一处就有一个能看见的怪现象：
  1. `ChatInput.tsx`：`onSend(text, overrides)` —— 附件以 `overrides.image` 跟着这次发送走。⚠ 这个 prop **不能收窄成 `(text: string) => void`**，收窄后类型对不上、WelcomeScreen 也传不进来。选图后立刻发送时，本轮闭包里的附件状态是旧值，`overrides` 就是为这个竞态存在的（与首屏卡片的 `{agent:true}` 同一条理由）。`submit()` 与发送按钮的 `disabled` **仍然只认文字**，纯图无文字发不出去。
  2. `useChat.run()`：把 `imageContextText(overrides?.image)` 塞进请求体的 `image_context`（**裸文本 + 原问题**，由后端统一拼模板），同时在 `payloadHistory` 里用 `withImageContext()` 给带图的历史消息补前缀——**不补的话追问第二轮图片上下文就丢了**。
  3. `ChatMessage.tsx` 的 user 分支：气泡上方挂 `ImageResultBlock`；`message.content` 保持用户原样输入的文字，图片内容**不拼进去**（渲染和历史回传是两条路，拼了会重复）。
- **`Message.image` 存 `VisionPayload`（解析结果），绝不存原图 base64**：`useChat` 会把整个 conversations 写进 localStorage（约 5MB 配额），base64 动辄几 MB，塞进去是**静默**失败——写不进去也不报错，用户只会发现历史对话莫名其妙少了。原图用完即弃，也不落盘。
- **附件按钮不按 `vision_available` 置灰**：那个字段读的是「最近一次真实调用的成败」，刚起服务时偏乐观，过时了也不一定翻——让用户点了拿到真实中文报错，比按钮灰着但实际可用要好。
- 新增了 `ImageResultBlock`（**不接 `SourcePanel`**，与图谱/数据库块同一条理由：那是带 `[n]` 编号的问答对）。它和那两个块不同的一点是**没有 `mb-3`**——它是用户气泡的兄弟节点，间距由父容器的 `gap-2` 管。
- **对话历史（服务端持久化）的前端要点**，细节见 `对话历史与反馈.md`：
  - `lib/api.ts` 里那 8 个函数是**唯一的 snake_case ↔ camelCase 边界**（后端 `schemas.py`
    一律 snake_case，组件一律 camelCase），别让转换漏出去。⚠ 它们**都带 `AbortSignal.timeout`**：
    这些调用不在「用户盯着转圈的等待路径」上，一个被黑洞吞掉的连接**不会有任何报错**——
    只会让侧栏永远停在同步中、点历史毫无反应，且**永远不降级**（降级的触发条件就是「失败了」）。
  - ⚠ **`Sidebar` 那个搜索 effect 的依赖数组是 `[query, composing]`**，`conversations` 走
    `conversationsRef`。把 `conversations` 放进依赖里，`patchMessage` 会在流式输出时
    **每毫秒重置防抖计时器**，结果就是「正在输入的那次搜索永远排不上号」。
    ⚠ **`composing` 必须在依赖里、不能只挂事件**：中文输入法组合期每次按键都触发
    `onChange`，值是 `gong`、`gong'ying` 这种**拼音中间态**——不挡住的话每敲一个字母就发一次
    搜索请求，且那个词必然 0 命中 → 列表在打字过程中闪空；更糟的是**残值会留在框里**，
    只要搜索框非空，列表就一直是搜索结果的快照，**之后新问的对话一条都不出现**
    （用户会报成「侧栏永远显示暂无历史对话」，实测后端日志里就有 `q=gong`、`q=gong'ying`
    两条真实请求）。组合期间不发请求也不动 `hits`（`setHits(null)` 会让列表整块闪一下），
    由 `compositionend` 翻转标志后让 effect 带着最终选定的词再跑一次。
  - ⚠ **`historySynced` 三态**，只在 `=== false` 时说话（同 `webConfigured` 的约定）。
    它从 `useChat` 经 `page.tsx` 传给 **`Sidebar`**（不是 `ChatInput`，别照着开关那条路径抄）。
  - ⚠ **`page.tsx` 的 `activeConversation?.remote` 加载中分支必须排在 `messageCount === 0` 之前**。
  - **点搜索结果 → 跳转 + 标黄**（2026-09-21 加）：`onSelect(id, jump)` 的第二个参数**不能省**
    （TS 不报错），`keyword` 必须在 `clearSearch()` **之前**读 `query`。机制与那两个抢滚动
    容器的 effect 见 `对话历史与反馈.md`。
  - **清空全部**（2026-09-21 加）：`onDeleteAll` 的签名与 `onDelete` **形状不同**（`async`
    且**会抛**），侧栏 `runClear` 的 catch 就地显示后端那句中文。⚠ 两个机械性的坑：
    ① `useChat` 那个 `flush` 的返回值改造与「清空先等在途那一发 PUT」是**耦合的**
    （改一处要看另一处，理由见 `flush` 的注释）；② **`setPendingJump(null)` 必须清**，
    否则它会**永久**压住自动滚到底。三个守卫各自挡什么见 `对话历史与反馈.md`。
  - 侧栏那行「未同步」提示、以及**搜索框里别写 `focus:ring-*`**（同 `ChatInput` 那条：项目里的
    阴影是任意值 `shadow-[…]`，与 Tailwind 的 ring 合成变量互斥，写了会**静默不生效**）。
  - ⚠ **行尾的「⋯」菜单是 `position: fixed` + 打开时用 `getBoundingClientRect()` 算坐标，
    不是 `absolute` 挂在行上**。两个理由都不能省：① 列表在 `overflow-y-auto` 容器里，
    `absolute` 会被裁掉下半截（滚到底时最后一行贴着下沿，菜单只露一半）；② 它挂在 `aside` 下
    而**不在**那一行的 DOM 里 —— 否则点「删除」会冒泡到行的「切过去」`onClick`，删完还跳过去。
    配套的两条：打开的那次点击**必须 `stopPropagation()`**（既挡行的 onClick，也挡下面那个
    `document` 的「点别处关闭」—— effect 注册监听发生在本次事件之后，不挡的话菜单会
    **开了就立刻被自己关掉**）；关闭来源要四个齐全（点别处 / Esc / resize / **capture 阶段的
    scroll** —— 列表是在内层容器里滚的，冒泡阶段收不到）。⚠ 菜单开着的那一行，「⋯」要
    `visible`（鼠标移到菜单上时已经离开该行，否则按钮会在菜单还开着时先消失）；
    显隐用 `invisible` 而非 `hidden`，后者会改布局让整行文字抖一下。
